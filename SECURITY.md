# Security Policy

## Supported versions

Conferencier is pre-1.0. Security fixes are released only as a new version; older releases are not patched.

| Version                  | Supported |
| ------------------------ | --------- |
| latest `0.0.x` release   | ✅        |
| older releases           | ❌        |

## Reporting a vulnerability

**Please do not report security vulnerabilities through public issues, pull requests or discussions.**

Report them privately through GitHub instead: open the [Security tab](https://github.com/Komix42/conferencier/security) and choose **Report a vulnerability** (or go directly to [the advisory form](https://github.com/Komix42/conferencier/security/advisories/new)).

Please include as much of the following as you can:

- the affected crate (`conferencier`, `conferencier-derive`) and version,
- a description of the issue and its potential impact,
- a minimal reproduction (code, TOML input, steps),
- your Rust version and operating system, if relevant.

## What to expect

Conferencier is maintained by a single person in their spare time, so there are no guaranteed response or fix times. Every report is taken seriously and will be looked at as soon as possible.

- Further communication takes place in the private advisory created by your report, where you can also follow the progress.
- Once a fix is ready, a new version is published to crates.io, a GitHub security advisory is published and, where appropriate, the issue is reported to the [RustSec advisory database](https://rustsec.org/). Affected versions may be yanked.
- You will be credited in the advisory unless you prefer to stay anonymous.

Please keep the details private until a fix has been released.

## Scope

Relevant reports include, for example, memory unsafety, panics or excessive resource use triggered by untrusted TOML input, problems in file handling (such as atomic writes leaving corrupted or exposed files), and code generated by `#[derive(ConferModule)]` that is unsound or behaves differently than documented.

Vulnerabilities in dependencies should be reported to their maintainers. If such a vulnerability affects conferencier in a specific way, a report here is still welcome.
