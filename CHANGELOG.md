# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- Moved the derive macro's cross-crate trybuild suite into the unpublished `derive-tests` workspace member, and added its `derive-msrv-tests` copy with Rust 1.85 snapshots that CI runs on the MSRV. Disabled the derive crate's own doctests, so `cargo test` also succeeds from the published derive archive; its examples moved to `conferencier-derive/doc/` and run as doctests of the unpublished `docs-tests` member (formerly `readme-tests`).
- Unsupported `#[confer(...)]` attributes are reported by name together with the list of supported struct or field attributes, e.g. ``unsupported attribute `defualt` for #[derive(ConfigScope)]; supported field attributes: …``.
- Documentation examples in `conferencier`, the README and the derive macros are now doctested with `deny(warnings)`. The README example no longer warns about the unread `request_count` field; it now updates the field under a short-lived write lock. The guide's reload and error examples use their helper functions, and the migration guide's current-API example is no longer ignored.

### Fixed
- Code generated by `#[derive(ConfigScope)]` no longer triggers clippy's `unused_async_trait_impl` (pedantic) and `significant_drop_tightening` (nursery) lints in user crates: `load`/`save` release their internal scope lock explicitly and return `impl Future` instead of being `async fn`. Generated impls are marked `#[automatically_derived]`. Behavior and the trait API are unchanged.
- The `advanced_usage` example writes its snapshot next to the example binary (e.g. `target/debug/examples/`) instead of `conferencier/target/`, so it honors the workspace target directory and `CARGO_TARGET_DIR`, no longer writes into the package sources, and prints a path with consistent separators.
- Derived `ConfigScope` implementations state their required `Send + Sync + 'static` bounds explicitly. A non-`Send` or non-`Sync` field, including an ignored field, now produces the direct trait-bound errors instead of additional cascading errors from the generated futures.

## [0.1.0-beta.1] - 2026-11-19

### Added
- Added the public `IoOperation` enum and `Error::SaveFileTaskJoin` for failures to join the blocking save task. Added `Error::io_error`, `io_error_with_operation`, `parse_error` and `serialize_error` constructors; the library-created save-specific variants have no public constructors ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E2, E5).

### Changed
- **Breaking:** `Error::Io` is now non-exhaustive and includes `operation` and `target_path`; use its public constructors rather than constructing the variant. File-method errors identify their operation and `save_file` destination. `Display` now describes the operation, escapes paths and omits the wrapped source ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E1–E3, E5, E6).
- **Breaking:** `Error::Parse` and `Error::Serialize` are now non-exhaustive struct variants with optional file and save-target paths, respectively. Their `Display` messages no longer repeat the wrapped source; inspect `source()` for parser and serializer diagnostics ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E1, E3, E4, E5, E6).
- **Breaking:** `Error::SaveFileCleanup` is non-exhaustive and includes `target_path`. Its `Display` includes the cleanup error but not the original save error; its source remains the original save error. A blocking-task join failure is reported separately as `SaveFileTaskJoin` ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E1–E6).
- **Breaking:** The key-error constructors are renamed with an `_error` suffix: `Error::missing_key_error`, `type_mismatch_error`, `value_parse_error` and `unknown_key_error`. Their argument types and order are unchanged; the old names are removed without aliases ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E5).
- **Breaking:** `Error::MissingKey`, `TypeMismatch`, `ValueParse` and `UnknownKey` store the formatted table path in `table_path` instead of `path`, and each variant is `#[non_exhaustive]`: patterns outside the crate must include `..`, and the constructors create these variants. The `ConfigTable` method parameter is documented as `table_path`; existing implementations keep compiling ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E5).
- `conferencier` depends on the exactly matching `conferencier-derive` version (`=0.1.0-beta.1`), so Cargo cannot pair the library with a different derive release ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md), audit finding A8).
- Non-finite `f32` values, including infinities and NaNs, now load in scalar and vector fields and round-trip; NaN sign and payload are not preserved ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) F1).
- Save-time `u64` and `usize` range errors no longer include the raw value; vector errors continue to include the element index ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) E7).
- **Breaking:** `set_string` accepts `impl Into<String>`, and vector setters accept iterators instead of requiring owned vectors. Calls using `.into()` without a concrete target type may need adjustment; see RFC-0011 S1–S3 ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md)).
- **Breaking:** `ConfigStore`'s `Debug` output now lists top-level keys without configuration values, and reports when it cannot read keys because the store is locked ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) D1–D2).
- **Breaking:** the normal Tokio dependency now enables only `sync`, `rt` and `fs`; applications that relied on other Tokio features being enabled transitively must enable them directly ([RFC-0011](docs/devel-0.1.x/RFC-0011_api_polish_before_0.1.md) T1–T2).
- Derive-generated code now uses fully qualified `core` and `std` paths so caller names cannot shadow generated code. Unsupported-field diagnostics explain type-alias limitations, references and nested vectors ([AUDIT-001 B1, B5](docs/devel-0.0.x/AUDIT-001_quality_0.0.8.md)).
- Derive-generated code names the `conferencier` dependency with an absolute path, such as `::conferencier`, so a local item named `conferencier` no longer breaks or redirects it. The relative path is used only when no `conferencier` dependency is found ([AUDIT-002 A1](docs/devel-0.1.x/AUDIT-002_quality_0.1.0-beta.1.md)).

### Fixed
- Corrected the beta installation command and completed error-handling and runtime guidance, including examples for synchronous loading, error sources and selective scope `Debug`.

See the [migration guide from 0.0.8](conferencier/guide/migration.md#from-008-to-010-beta1).

## [0.0.8] - 2026-11-17

### Added
- A runnable example application, [`examples/uptime-monitor`](examples/uptime-monitor/README.md): an Axum status page and a background worker checking TCP targets, configured by one store with a scope per component. It demonstrates runtime state in ignored fields, application-side validation, an all-or-nothing explicit reload and export of the effective configuration. It is an unpublished workspace package, so the library crates gain no dependencies.
- A runnable [`examples/folder-indexer`](examples/folder-indexer/README.md) application: it scans folders, reports their contents and optionally creates a JSON catalog. Console commands manage and save its own configuration, demonstrating defaults, nested and optional tables, and runtime state in shared scopes. Catalogs are created only at new paths, without overwriting existing files.
- A runnable [`examples/modular-agent`](examples/modular-agent/README.md) application: independent components own and save their configuration sections, publish and subscribe to events, and continue independently when another component is disabled or misconfigured. A single persister serializes writes to the shared configuration file.

See the [migration guide from 0.0.7](conferencier/guide/migration.md#from-007-to-008).

## [0.0.6] - 2026-11-15

### Added
- `Error::SaveFileCleanup` reports both the original save failure and a failure to remove its temporary file.

### Changed
- **Breaking:** `ConfigStore::save_file` validates the final path component before creating a temporary file and rejects symlinks (including dangling links), other non-regular targets and all Windows reparse points with `InvalidInput`. Parent-directory links and regular files with multiple hard links remain supported.
- On Unix, `ConfigStore::save_file` establishes an existing target's observed `rwx` mode bits on the temporary file before writing, instead of replacing them with creation defaults. New targets still use normal creation policy; ownership, ACLs and other metadata are not preserved.
- `ConfigStore::save_file` no longer deletes the target and retries when replacement fails with `AlreadyExists`; it returns the error instead.
- Implemented the public error traits with the standard library, removing the `thiserror` dependency.

See the [migration guide from 0.0.5](conferencier/guide/migration.md#from-005-to-006).

## [0.0.5] - 2026-11-13

### Added
- Expanded rustdoc for the complete public API, with examples, conversion and error semantics, snapshot behavior, scope lock guidance and the current file-write limitations. The READMEs explain scopes, the `derive` feature and `#[confer(...)]`, and include the updated reload examples.
- Public `table_path::{section_path, child_path, element_path}` helpers build the derive's diagnostic paths in manual `ConfigScope` and `ConfigTable` implementations, with or without the `derive` feature ([RFC-0006](docs/devel-0.0.x/RFC-0006_strict_unknown_keys.md)).
- `#[confer(deny_unknown_keys)]` rejects unmapped keys during load, and `Error::UnknownKey` reports them with the formatted table path and raw key ([RFC-0006](docs/devel-0.0.x/RFC-0006_strict_unknown_keys.md)).

### Changed
- `ConfigStore::save_file` uses a temporary filename independent of the target filename, so saving files with long valid names no longer exceeds the filesystem's per-component filename limit.
- **Breaking:** A struct deriving only `ConfigTable` rejects `#[confer(section = "...")]` instead of silently ignoring it. Remove the attribute, or derive `ConfigScope` as well if a top-level scope is intended ([RFC-0008](docs/devel-0.0.x/RFC-0008_table_section.md)).
- **Breaking:** Missing table `T` and table `Vec<T>` fields now follow the same rule as scalar fields: use an explicit fallback, use `None` for an `Option`, or return `Error::MissingKey`. `#[confer(table, field_defaults)]` explicitly decodes a missing single table from an empty table; `#[confer(table, default)]` uses the field type's Rust `Default` instead ([RFC-0007](docs/devel-0.0.x/RFC-0007_default_expressions.md)).
- **Breaking:** `#[confer(default = <expr>)]` takes a Rust expression of exactly the field's type, without implicit literal conversions; `#[confer(default)]` uses the field type's Rust `Default`. Both forms are accepted on table fields, but rejected on syntactically recognized `Option` fields. Defaults run only for missing keys and are saved as ordinary values ([RFC-0007](docs/devel-0.0.x/RFC-0007_default_expressions.md)).
- **Breaking:** Empty `Vec<T>` table fields are now saved as `key = []` instead of being omitted, so they round-trip as empty even when loading requires a value. TOML does not allow adding `[[key]]` entries after a static array, so remove or replace the array first ([RFC-0007](docs/devel-0.0.x/RFC-0007_default_expressions.md)).
- **Breaking:** `Error::MissingKey`, `TypeMismatch` and `ValueParse` now store the formatted table path in `path` instead of `section`. Their constructors also take a formatted path; diagnostics quote section and key segments when needed, and non-table top-level entries use an empty path with the entry name as the key. Scalar-array conversion errors identify the zero-based element index ([RFC-0006](docs/devel-0.0.x/RFC-0006_strict_unknown_keys.md)).
- **Breaking:** Renamed the public API to `ConfigStore`, `ConfigScope`, `SharedScope`, `ConfigTable` and `Error`; `from_confer` is now `from_store`, the derive feature is `derive`, and the old public modules and `value_parse_owned` helper are removed. See [RFC-0005](docs/devel-0.0.x/RFC-0005_api_redesign.md) for the full migration.
- **Breaking:** `ConfigStore` is a cloneable handle whose clones share one document; `SharedConfer` is gone. Its in-memory methods are synchronous (no `.await`), and only `from_file`, `load_file` and `save_file` stay async. The store uses `std::sync::RwLock` and recovers from a poisoned lock.
- **Breaking:** `from_string` is now `from_str` (`ConfigStore` also implements `FromStr`), `from_file` is async and replaces `from_file_async`, and there is no blocking file constructor. `get_section_table`, `set_section_table`, `section_exists` and `add_section` are now `get_section`, `set_section`, `has_section` and `ensure_section`; `remove_section` returns `()`.
- **Breaking:** `ConfigScope::from_store` is synchronous, and `from_store`, `load` and `save` borrow the store (`&ConfigStore`) instead of taking it by value.
- **Breaking:** `ConfigScope` no longer uses `#[async_trait]`: `load` and `save` return `impl Future<Output = Result<()>> + Send`, so generic code can spawn them. Manual implementations drop `#[async_trait]` and keep `async fn load`/`async fn save`. The `async-trait` dependency is removed.
- **Breaking:** The default section name is the full struct name; a leading `Confer` word is no longer stripped. A `ConfigScope` such as `ConferApp` without `#[confer(section = ...)]` fails to compile with a message naming both choices: `section = "App"` keeps the 0.0.4 section, `section = "ConferApp"` uses the full name. This check stays through 0.1.x and is removed in 0.2.0, so upgrade from 0.0.4 through a 0.1.x release, or add an explicit section before upgrading to 0.2.0 directly.
- **Breaking:** Quoted nested segments of diagnostic paths escape U+0080–U+009F as uppercase `\uXXXX`, like the other control characters, instead of writing them literally ([RFC-0006](docs/devel-0.0.x/RFC-0006_strict_unknown_keys.md) P2).

See the [migration guide from 0.0.4](conferencier/guide/migration.md#from-004-to-005).

### Removed
- The direct `toml` dependency of `conferencier-derive`; generated code and applications can use the `conferencier` re-exports.
- The unused `serde` dependency, so builds of `conferencier` no longer compile the `serde_derive` proc-macro.

### Fixed
- `#[confer(deny_unknown_keys)]` now accepts following attributes and trailing commas in the same `#[confer(...)]` list instead of mistaking them for a value.
- Concurrent `save_file` calls to the same path, including calls through cloned stores, use separate uniquely named temporary files instead of a shared `<filename>.tmp`, avoiding the previous temporary-file corruption. Every successful call installs one complete snapshot; which of several calls wins is unspecified. On platforms where replacement removes the existing target before retrying the rename, concurrent saves can still fail if another save removes the target first. The temporary file is removed when the write or rename fails.

## [0.0.4] - 2026-11-11

### Added
- `ConferTable`, a synchronous trait for plain nested configuration values, and `Confer::set_section_table` for atomic replacement of a complete section.
- `#[derive(ConferTable)]` and the `#[confer(table)]` field attribute map nested TOML tables to plain structs. A table field can be `T` (a sub-table such as `[App.server]`), `Option<T>` or `Vec<T>` (an array of tables such as `[[App.upstream]]`), in modules and in other tables, to any depth. An absent `T` is loaded from an empty table, so its fields' defaults apply; an absent `Vec<T>` loads as empty, unlike a scalar `Vec` without `default`; an empty `Vec<T>` is not written on save. Errors inside nested tables name the full path, for example `invalid value at App.upstream[1].weight: value out of range for u32`. One struct can derive both `ConferModule` and `ConferTable`.
- The `nested_tables` example and a "Nested tables" section in the README.
- The README explains what saving does to a hand-written configuration file: comments, key order and value notation are not preserved, and a module's `save` removes unknown keys and sub-tables from its section, including misspelled ones. Saving is recommended mainly for generating an initial configuration file.
- README sections on the scope of the crate, listing what it intentionally leaves out (formats other than TOML, layered sources, hot reload, validation beyond value types and format-preserving saves), on reloading configuration manually, and on keeping runtime state in a module through ignored fields, which later loads keep.
- API documentation for the variants and fields of `ConferError`, the `Result` alias and the `conferencier-derive` crate. The documentation of `ConferModule::load` and `ConferModule::save` now says what they change and that they lock the module, so a task must not call them while it holds a guard of that module; the README explains this as well.
- `docs/BACKLOG.md` collects known technical debt and ideas for future versions, which were previously spread over the future-work sections of the RFCs.
- A security policy (`SECURITY.md`) for reporting vulnerabilities privately through GitHub, a code of conduct, and issue and pull request templates.

### Changed
- **Breaking:** `ConferError` is now `#[non_exhaustive]`, so future releases can add error variants without a breaking change. A `match` on `ConferError` outside this crate needs a wildcard arm (`_ => ...`); constructing variants and matching individual variants work as before.
- **Breaking:** `#[confer(init = ...)]` was removed and `#[confer(ignore)]` takes an optional Rust expression initializer. Ignored fields are now initialized once, after loaded fields have converted successfully.
- The derived `from_confer` builds the module directly from the values read from the store instead of creating a default instance and loading into it, so loaded fields no longer need to implement `Default`.
- Derived modules load and save whole sections. `from_confer` and `load` convert a single snapshot of the section, and `load` updates the module only if every field converts, so a failing `load` leaves the module unchanged (previously the fields before the failing one were already updated). `save` converts the whole module first and then replaces the section in a single write: readers never observe a half-saved module, and a conversion error such as a `u64` above `i64::MAX` leaves the store unchanged (previously earlier fields were already written). Such conversion errors are reported before a section that is not a table. `load` of a module without loaded fields now also fails when its section exists but is not a table.
- The "unsupported field type" compile error now says how to nest a struct: `#[confer(table)]` on the field and `#[derive(ConferTable)]` on the type.
- The crate description and the README introduction present conferencier as a minimal, single-purpose library.
- The minimum supported Rust version is lowered from 1.88 to 1.85, the lowest version that the 2024 edition and the `toml` 1.x dependency allow, so both crates build with older toolchains.

See the [migration guide from 0.0.3](conferencier/guide/migration.md#from-003-to-004).

### Fixed
- A required `Datetime` field (plain type without `default`) now compiles and loads; a missing key fails with `MissingKey`.
- Ignored fields have no TOML key and no longer take part in duplicate key detection, so a struct that was rejected only because an ignored field was named like the key of another field now compiles.

## [0.0.3] - 2026-11-08

### Added
- The `ConferModule` trait is re-exported at the crate root next to the derive macro of the same name, so `use conferencier::ConferModule;` is enough to both derive the trait and call `from_confer`/`load`/`save`.
- Re-exported the `toml` crate (`conferencier::toml`) and its datetime type (`conferencier::Datetime`), so applications can use the TOML types from the public API without matching `toml` versions themselves.

### Changed
- The minimum supported Rust version is now 1.88 and is declared via `rust-version`, so older toolchains get a clear error instead of a compile failure.
- **Breaking:** the default section name strips a leading `Confer` only once and only as a separate CamelCase word, as documented. `ConferenceSettings` now maps to `[ConferenceSettings]` (previously `[enceSettings]`) and `ConferConferApp` to `[ConferApp]` (previously `[App]`). `ConferApp` still maps to `[App]`. If your config files rely on the old names, add `#[confer(section = "...")]`.
- Updated error derivation to `thiserror` 2 without changing public error variants, messages or source chaining.
- Updated macro crate-name resolution to `proc-macro-crate` 3, fixing derives for renamed, workspace-inherited dependencies.
- Updated procedural-macro parsing to `syn` 3.
- **Breaking:** both crates now use `toml` 1.2 (TOML 1.1). Public TOML values, tables, datetimes and errors are no longer interchangeable with types from `toml` 0.9. Prefer the `conferencier::toml` and `conferencier::Datetime` re-exports, or update your direct TOML dependency.
- In the new datetime API, `Time::second` and `Time::nanosecond` are optional, preserving omitted components instead of replacing them with zero.

See the [migration guide from 0.0.2](conferencier/guide/migration.md#from-002-to-003).

### Fixed
- Both crates can be published together with `cargo publish --workspace`; the versioned dev-dependency of `conferencier-derive` on `conferencier` that formed a publish cycle is now path-only.
- The published `conferencier` package no longer ships a stray `target/advanced_usage_snapshot.toml` generated by the advanced example.
- Both published crates now include the `LICENSE-MIT` and `LICENSE-APACHE` texts required by their licenses.
- The README quick start now compiles and runs (it lacked the trait import, a default for `features` and the `tokio` dependency). The crate README is now the crate-level documentation and runs as a doctest, so it stays correct.
- The `conferencier-derive` README no longer suggests that the derive works without depending on `conferencier`.
- Invalid `Datetime` defaults such as `#[confer(default = "tomorrow")]` are rejected at compile time with a clear error instead of panicking at runtime.
- Code generated for `Datetime` defaults no longer requires `toml` as a direct dependency of the user's crate.
- Fields named like locals of the generated `save()` (for example `store` or `module`) no longer break compilation of the derived code.
- Fields declared with raw identifiers (for example `r#type`) map to the TOML key `type` instead of `r#type`.
- Negative numeric defaults such as `#[confer(default = -1)]` or `[-1, 2]` are accepted for signed integer and float fields; on unsigned fields they produce a clear compile error.

## [0.0.1] - 2025-09-29

### Added
- Core `conferencier` crate providing an async, TOML-backed configuration store with typed getters and setters.
- `#[derive(ConferModule)]` procedural macro for generating load/save implementations.
- Shared `Confer` store API supporting synchronous and asynchronous file I/O, atomic writes, and section/key management.
- Comprehensive error handling via `ConferError` with rich diagnostics for type mismatches and parsing issues.
- Integration and unit tests covering store operations, module round-trips, and concurrency scenarios.
- Examples demonstrating advanced usage patterns, including file-backed configuration updates.
- Developer documentation (`docs/`) describing architecture decisions and implementation details.
